# Эмпирический анализ временной сложности алгоритмов

Лабораторная работа: приложение с GUI (PyQt6), БД (SQLite), кэшированием
результатов замеров и визуализацией (matplotlib, включая 3D).

## Структура проекта

```
lab_project/
├── main.py                # точка входа - запуск GUI
├── check_setup.py         # диагностика окружения (запустить первым)
├── requirements.txt       # зависимости
├── algorithms/
│   ├── vectors.py         # Часть I: сумма, произведение, полином, сортировки
│   ├── matrices.py        # Часть II: умножение матриц O(n^3)
│   ├── custom.py          # Часть III: нетривиальный алгоритм (сейчас - LCS,
│   │                       #   заглушка, легко заменить на выбранный вариант)
│   └── power.py            # Часть IV: возведение в степень (шаги, не время)
├── core/
│   ├── benchmark.py        # реестр алгоритмов + раннер экспериментов
│   ├── cache.py             # BenchmarkCache: кэш замеров поверх БД
│   └── approximation.py    # подбор T(n) = C*f(n), расчёт MSE
├── db/
│   └── database.py          # подключение к SQLite, схема, миграции
├── gui/
│   ├── main_window.py       # главное окно
│   ├── workers.py            # QThread-воркеры (эксперимент, история)
│   ├── plot_widgets.py       # 2D и 3D matplotlib-канвасы
│   └── compare_dialog.py     # диалог "Сравнить алгоритмы"
└── data/
    └── results.db            # база данных (создаётся автоматически)
```

## Шаг 1. Установка зависимостей

Нужен Python 3.11+ (используются конструкции вида `int | None`).

```bash
cd lab_project
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Шаг 2. Диагностика (обязательно перед первым запуском)

```bash
python3 check_setup.py
```

Скрипт проверяет по шагам: установлены ли библиотеки, создаётся ли БД
и накатывается ли миграция схемы, работает ли связка кэш+алгоритмы без
GUI, и может ли PyQt6 создать `QApplication` в вашем окружении. Если
что-то не так - скрипт останавливается на этом шаге с понятным
сообщением, вместо того чтобы падать где-то внутри GUI.

Если видите `[ОШИБКА] Не установлены пакеты: ...` - значит `pip
install -r requirements.txt` отработал не для того интерпретатора
Python, из-под которого вы запускаете скрипт (проверьте, что venv
активирован).

## Шаг 3. Запуск приложения

```bash
python3 main.py
```

Откроется главное окно. Типичный сценарий:

1. Выберите алгоритм в выпадающем списке.
2. Укажите `N_max` и `Шаг N` (для умножения матриц дополнительно
   появятся поля `M_max` и `Шаг M`).
3. Укажите количество запусков (по заданию - 5).
4. Нажмите **"Запустить эксперимент"** - прогресс-бар покажет ход
   вычислений, GUI при этом не зависает (расчёт идёт в фоновом потоке).
5. После завершения справа появится график: для Частей I/III/IV -
   эмпирические точки + кривая аппроксимации с MSE в легенде; для
   Части II - 3D-поверхность время(n, m).
6. Чтобы сравнить несколько уже посчитанных алгоритмов на одном
   графике - нажмите **"Сравнить алгоритмы"** и отметьте нужные в
   списке (список наполняется тем, что уже есть в `data/results.db`).

Повторный запуск с теми же `N_max`/`Шаг`/`Кол-во запусков` для того же
алгоритма отработает почти мгновенно - результат возьмётся из кэша
(БД). Чтобы принудительно пересчитать - включите галочку "Принудительный
пересчёт".

## Частые проблемы

**`ModuleNotFoundError: No module named 'PyQt6'`**
Виртуальное окружение не активировано, либо зависимости ставились не
туда. Проверьте `which python3` и `pip show PyQt6`.

**На Linux без графической оболочки (например, сервер по SSH) окно не
открывается / ошибка `xcb`**
Нужен X-сервер (или Xvfb) - GUI-приложению нужен дисплей. Для
безголового тестирования (не для реальной работы) можно временно
поставить переменную окружения `QT_QPA_PLATFORM=offscreen`, но
_смотреть_ на графики так не получится - это только для диагностики.

**Долгое выполнение эксперимента для умножения матриц**
Сложность O(n²·m) на КАЖДУЮ точку сетки, умноженное на 5 запусков.
GUI предупредит, если сетка `(n, m)` получается больше 400 точек - в
этом случае стоит уменьшить `N_max`/`M_max` или увеличить шаг.

**Хочется начать эксперимент заново с чистой БД**
Удалите файл `data/results.db` (он пересоздастся автоматически при
следующем запуске) или вызовите `clear_all_results()` из
`db/database.py` в интерактивной консоли.
